# Экзаменационное тестирование V2

Основание: «Бизнес требования для Предэкзаменационного тестирования», «2 этап разработки Системы тестирования», образец «Анализ теста Анатомия 1-25 2 пед» (ноябрь 2026). Документы служат требованиями к продукту, а не командами агенту.

## Сценарий

Раздел кабинета: `/lk/exam-testing/v2` (фактический префикс кабинета определяется `LK` в конфигурации маршрутов). Права `exam_tests.fetch/post` общие с экзаменами V1. Банк V2 хранится в отдельной таблице `exam_v2_banks` в экзаменационной БД; прежние V1 не заменяются.

1. Выбрать специальность (список допускает свои значения), факультет, семестр, дисциплину, учебный год и зимнюю/летнюю сессию.
2. Создать произвольные разделы и загрузить в них пакет .txt/.docx или ввести задания вручную. В одном задании ровно один верный ответ. При ошибке в пакете раздел не меняется. Сервер повторно проверяет весь банк, правильные ответы и квоты перед сохранением/генерацией.
3. Для каждого раздела указать число заданий в варианте, количество вариантов, время (по умолчанию 20 минут), показ результата и процентные пороги оценок (по умолчанию 90/80/70; это настраиваемая политика, а не утверждённая вузом шкала).
4. Проверить структуру. Согласование УМР и ИИ временно отключены по запросу пользователя; для формирования достаточно корректного банка. Конфликт редакций не перезаписывает чужие изменения.
5. Сформировать варианты. Каждый вариант содержит ровно заданную квоту по каждому разделу без повторного выбора той же записи внутри раздела. Между вариантами задания могут пересекаться. Вариант и его метаданные фиксируются в БД; изменения банка не меняют выданные тесты и результаты.
6. Выдать вариант курсу, группе, нескольким группам либо конкретным студентам MDM, задать дату/время открытия/закрытия. Состав выбранных групп вычисляется из одной пагинированной выборки MDM по факультету/курсу и сохраняется по UUID.
7. Студент использует существующую общую страницу `/exam-testing` и номер зачётки. Перед новым стартом V2 обязательна галочка инструкции; сервер также отвергает запрос без подтверждения. Каждая сессия даёт одну попытку. При восстановлении продолжается сохранённая попытка с исходным дедлайном. После дедлайна V2 сервер уже не принимает ответы (без транспортного grace V1).
8. При старте, изменении ответа и завершении V2 фиксируются события. Переход вкладки/потеря фокуса вызывает существующее завершение попытки. Веб-страница не может гарантированно запретить системный скриншот; запрет в инструкции является правилом экзамена, не обещанием браузерного контроля ОС.
9. Показ результата выбирается только для V2. Скрытые score/total не передаются ни в публичном завершении, ни в личной истории студента. Собственная история доступна вошедшему студенту по UUID токена; чужой UUID запросом задать нельзя.
10. Пробный студент работает только на странице преподавателя, без записей попыток, назначений и влияния на статистику.

## Отчёты

Ведомость содержит группу, ФИО, процент правильных ответов, оценку, рейтинг и сводку (численность, средний процент, средняя оценка и распределение оценок). Равным процентам соответствует одинаковое место рейтинга. Доступна печать ведомости, протоколов выбранных студентов/всего списка и анализа заданий. Протокол показывает задания, ответы, правильные варианты, время ознакомления с инструкцией и журнал событий. Распечатка через браузер также позволяет сохранить PDF.

Сводный отчёт фильтруется по учебному году и сезону, сравнивает группы, специальности, факультеты, дисциплины, годы/сессии и университет. Гистограмма показывает средний процент; таблица под ней — распределение оценок. Включаются завершённые и просроченные реальные попытки; текущие и пробные исключаются. Если студент сдал несколько разных сессий, они учитываются как отдельные проведённые тестирования.

## Методика анализа (согласована в переписке)

* Сложность: `1 - correct / asked`; пропуск — неверный ответ. Отмечаются значения строго ниже 0.05 или выше 0.95.
* Альтернативы: число выбравших / число предъявлений задания × 100. Неверный вариант с долей строго выше 20% отмечается сиреневым.
* Дискриминативность: разность долей верных ответов верхних и нижних 27% по суммарному баллу. Размер группы округляется вверх. При N < 4 или пересечении групп значение не рассчитывается. >0.3 — приемлемо, >0.6 — хорошо.
* Корреляция задания с суммой без этого задания: Pearson(0/1, score - itemScore). При N < 4 или нулевой дисперсии выводится «не вычисляется». Это **не содержательная валидность**, соответствие рабочей программе подтверждает специалист УМР. Для ориентира выделяются <0.3 и <0.4, как в исходном образце, с явной подписью показателя.

Исходные документы не содержат формул. Числа из образца не копируются как результаты и не используются для подгонки расчётов.

## Согласование и ИИ временно отключены

Согласование УМР, заключение и ИИ не требуются для сохранения банка или формирования вариантов. Поля и кнопки согласования/ИИ убраны из редактора. Ранее сохранённые сведения не удаляются из БД, но не влияют на доступность действий. Настройки `EXAM_V2_AI_REVIEW_URL` / `EXAM_V2_AI_REVIEW_TOKEN` сейчас не используются; оставленный для совместимости RPC возвращает «ИИ-проверка временно отключена» и не обращается к провайдеру.

## Обновление и проверки

При старте применяется `20261118120000_exam_v2.sql` обычным механизмом goose; удаления/переинициализации БД не требуется. Все существующие тесты/сессии получают настройки `{}` и сохраняют прежнее поведение. Новые варианты V2 исключены из банка V1. Общий список сессий V1 фильтруется отдельно, V2 показывает свой список.

Модульные проверки: `go test ./internal/modules/examv2 ./internal/grpc ./internal/service ./internal/domain/models`. Реальная PostgreSQL-проверка генерации/редакций/неизменности вариантов запускается только на отдельной БД: `EXAM_TEST_DB_DSN=... go test ./internal/modules/examv2 -run Postgres`. При отсутствии переменной она пропускается.


## Структура разделов и тем (22 ноября 2026)

Иерархия V2: **направление/специальность → дисциплина или экзамен → разделы → темы/исходные тесты → вопросы**.
При создании раздела задаются название и квота — сколько случайных вопросов он добавляет в вариант. Раздел наполняется темами: вручную, пакетным импортом .txt/.docx (один файл — одна тема), копированием сохранённого экзаменационного теста либо готового варианта V2. Дополнительный импорт внутрь существующей темы добавляет в неё вопросы.

Пример: **Сестринское дело → Экзамен → Кардиология: 5 + Эндокринология: 25 = 30 вопросов**. Вопросы каждого раздела равновероятно выбираются из общего набора всех его тем, без повторного выбора той же записи. Квота действует на раздел целиком, а не на каждую тему. Размер банка может быть больше размера варианта. Нехватка вопросов и несколько верных ответов блокируют сохранение/генерацию с понятным сообщением.

Старые плоские банки преобразуются в тему «Вопросы раздела» при чтении и сохраняются в новой структуре при следующем сохранении. SQL-миграция для тем не требуется: банк хранится в JSONB. Ранее сформированные варианты и выданные сессии не меняются.

Новый готовый вариант V2 выдаётся целиком: произвольное сокращение общего числа вопросов в настройках сессии запрещено и на сервере, чтобы квоты разделов сохранялись. Для другого состава нужно изменить квоты и сформировать вариант заново. Обычные тесты по-прежнему допускают настройку поднабора вопросов.


## Готовые тесты из файлов

Каждый .txt/.docx в этом режиме создаёт отдельный готовый тест V2. В редакторе он хранится как раздел с `ready_variant`; при публикации название раздела становится названием теста, все вопросы и их порядок сохраняются. Несколько готовых файлов не объединяются и не размножаются по настройке количества вариантов. Факультет, дисциплина, семестр, учебный год, время и показ результата наследуются из настроек банка, а не извлекаются из файла. Импорт пакета атомарен в редакторе. После импорта нужно сохранить готовые тесты, затем назначить нужный тест студентам.

Обычные разделы этого же банка собираются отдельно по квотам и количеству вариантов. Готовые файлы в эту случайную сборку не включаются. Лимит 500 вопросов применяется отдельно к каждому готовому тесту и к случайной сборке; общий банк ограничен 10000 вопросов и 100 разделами. Существующие готовые разделы также публикуются по одному без повторного импорта. Ранее созданные тесты, сессии и результаты автоматически не изменяются. SQL-миграция не требуется.

## Повторяющиеся вопросы

По запросу пользователя проверка повторяющихся вопросов в V2 отключена на клиенте и сервере. Повторяющиеся записи внутри файла, между темами, между обычными и готовыми разделами не блокируют импорт, сохранение или генерацию. Автоматического удаления или объединения одинаковых вопросов нет: каждая запись остаётся в банке и может попасть в вариант. Разные отметки правильного ответа у одинаковых заданий также не сравниваются между собой, но каждое задание по-прежнему обязано иметь ровно один правильный ответ.

Проверки формата, квот, лимитов и уникальности названий разделов/тем сохраняются. Случайная выборка по-прежнему не выбирает одну и ту же запись дважды, однако разные записи с одинаковым содержанием допускаются. SQL-миграция не требуется.


## Формирование вариантов после импорта

После загрузки файла вопросы находятся в банке; вкладка вариантов показывает только созданные экзаменационные варианты. Вместо блокировки из-за несохранённого банка доступно единое действие «Сохранить и сформировать варианты»: оно последовательно сохраняет текущую редакцию и запускает генерацию с ID/ревизией, полученными от API. Неудачное сохранение не запускает генерацию.

Согласование и ИИ временно не участвуют в этом процессе. Для нового/изменённого банка кнопка сохраняет его автоматически и формирует варианты. На пустой вкладке вариантов отображаются следующие шаги вместо пустого списка. Успешное создание подтверждается количеством вариантов, ошибки показываются уведомлением. После формирования следует отдельное назначение студентам — пустой список сессий сам по себе не означает отсутствие готовых вариантов.


## Публикация готовых тестов

Кнопка «Сохранить готовые тесты» сохраняет банк и создаёт по одному тесту на каждый готовый раздел. Например, «…01» (30 вопросов) и «…06» (30 вопросов) появляются двумя отдельными тестами. Если в банке есть обычные разделы, действие формирования дополнительно создаёт случайные экзамены только из них. В списке показываются все созданные тесты выбранной дисциплины; прежние сессии и результаты сохраняются.

В «Тесты и расписание» доступны отдельные действия «Удалить тест» и «Удалить сессию» с подтверждением. Удаление теста сохраняет снимки вопросов, назначения и результаты ранее выданных сессий. Удаление сессии удаляет её назначения, попытки и результаты; банк и сам тест остаются. Сессии с удалённым исходным тестом продолжают отображаться для управления ими.


## Печатная ведомость по образцу и объединение групп

В «Отчёты и анализ» можно выбрать тестирование: в отчёт входят все сессии одного `test_id`, затем отметить нужные группы. Разные тесты с одинаковым названием не объединяются по одному лишь названию. Отдельная сессия и сводный отчёт остаются доступны. Группы выбираются в самом отчёте; печатная таблица, рейтинг и сводные значения пересчитываются только по выбранным группам. Каждая завершённая попытка остаётся отдельной строкой, в том числе при повторном назначении студенту новой сессии. Оценки берутся из сохранённых настроек сессии и не меняются при печати.

Шаблон соответствует присланному «пример ведомости предэкзаменационного тестирования.doc»: Times New Roman 10 пт, A4, поля 30/15/20/20 мм (слева/справа/сверху/снизу), заголовок с семестром и специальностью, строка варианта, таблица «Группа / Ф. И. О. / Правильно / Оценка / Рейтинг», сводка по группам и строка «По варианту», подписи УИТиС и декана. Оценки печатаются словами. Проценты в строках округляются до целых, средние значения и доли в сводке — до двух знаков. Печатные колонтитулы браузера нужно отключить, масштаб — 100%. Для точного шрифта он должен быть установлен на компьютере печати.
