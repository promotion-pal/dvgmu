# Назначения экзаменов и фильтруемый справочник MDM

## Назначение в ЛК

В экзаменационном банке действие «Открыть доступ» задаёт время, параметры
прохождения и получателей: курс факультета, группу факультета либо выбранных
студентов. Списки и фильтры приходят из MDM. Нужны права `exam_tests.post`.

Назначение сохраняет текущий состав получателей, а не изменяющееся условие:
`exam_assignments(session_id, mdm_user_uuid)` с уникальностью пары и каскадным
удалением при удалении сессии. UUID — идентификатор пользователя MDM, не его
внутренний числовой ID. Смена группы или курса позже не переписывает ранее
выданный экзамен. Для нового состава создаётся новое назначение.

Курс определяется в MDM тем же способом, что `Student.ParseCourse`: по году
поступления в семизначном номере зачётки. Факультет — по первым двум цифрам.
Форма назначения запрашивает пользователей по наличию учебной записи (`profile_kind=student`).
Активация учётки ЛК и ручная роль STUDENT не требуются. Допускаются статусы
STUDYING, RESTORED, TRANSFERRED и неуказанный статус импортированных записей;
отчисленные, выпускники и академический отпуск исключены. Назначение группе требует факультет, курс и группу; назначение курсу — факультет и курс, чтобы
одноимённые группы разных факультетов не смешивались.

MDM возвращает получателей страницами (по 200 при выдаче назначения), без
запросов полного профиля для каждого человека. UUID дедуплицируются, отсутствие
выбранного студента/пустая выборка/недоступность MDM отменяют создание сессии.
Сессия и связи со студентами записываются одной транзакцией.

## Общая открытая страница

На `<домен портала>/exam-testing` студент вводит номер зачётной книжки.
Сервер точным фильтром MDM находит единственный UUID студента и возвращает
только его назначенные, открытые в данный момент экзамены. Ответ содержит ФИО, группу, факультет и курс только найденного студента;
номера зачёток, UUID и списки других студентов в ответ не включаются.
Если доступен один экзамен, сразу открывается его экран; отсчёт времени
начинается после кнопки «Начать тест».

При старте проверка выполняется повторно: запись MDM должна однозначно
определять студента, а в `exam_assignments` должна существовать связь с выбранной
сессией. Подмена токена другого теста или ФИО/группы в запросе не открывает его.
ФИО и группа результата заполняются из MDM, UUID сохраняется в
`test_attempts.mdm_user_uuid`. Недоступность MDM запрещает старт.

Это проверка по номеру зачётки, как согласовано для компьютерного класса;
вход в AD/ЛК не требуется. Сохранённые попытки в браузере разделяются по сессии
и SHA-256 номера зачётки: следующий студент не получает чужую активную попытку.
Номер зачётки не сохраняется в таблице назначений/попыток и не передаётся в URL.

Прежние экзаменационные сессии без назначенных UUID больше не доступны
анонимно. Преподаватель открывает доступ заново с выбором получателей.
Обычные тесты V1/V2 сохраняют прежний порядок регистрации по ФИО и группе.

## MDM: один фильтруемый запрос

Новый `contract.service.UserDirectoryService/UserDirectoryFetch` совместим
с существующим `UserService`: старые методы и форматы не меняются.
Есть HTTP-вариант с query-параметрами:

```text
GET /users?role=student&faculty_code=20&course=2&student_group=201&limit=50&include_facets=true
GET /users?role=staff&employee_department=1&employee_position=Doctor&user_status=active
GET /users?role=teacher&query=Иванов&limit=50&offset=50
```

Параметры: `role`, `query`, `user_status`, `faculty_code`, `course`,
`student_group`, `record_book` (точное совпадение), `student_status`,
`employee_department`, `employee_position` (должность из `users.position`), `limit`,
`offset`, `include_facets`, `profile_kind` (`student`/`employee`),
`active_students_only`. `role=employee` — синоним STAFF. Enum принимаются
как короткое/полное имя либо числовое значение. В Connect-запросе также можно
передать `user_uuids` для пакетного выбора конкретных людей.

`role` фильтрует ручные права входа, а `profile_kind` — наличие учебной/служебной
записи независимо от прав входа. Фильтры и особенности профиля применяются в SQL до пагинации. Несовместимые
студенческие/сотруднические фильтры, неизвестные enum и превышенный лимит
отклоняются. `limit` по умолчанию 50, максимум 200. Ответ содержит `users`,
`total`, `next_offset` (0 — последняя страница), `student_facets` при запросе.
Facets включают факультеты, курсы и группы целиком для выбранной роли/статуса,
чтобы интерфейс не запрашивал каждый справочник отдельно.

Возвращаются только UUID, ФИО, роли и соответствующие учебные/служебные
атрибуты. Паспорт, контакты, права и номера зачёток в ответ не входят.
На шлюзе FESMU общий справочник и `GET /users` доступны ADMIN; преподаватели
используют ограниченный `ExamAudienceFetch`, требующий `exam_tests.post` и
принудительно запрашивающий только студентов.

## Обновление

Сначала обновляется MDM с новым методом, затем FESMU API и фронт.
MDM подтверждает применённый `profile_kind` в ответе; если старый сервис
проигнорировал новый фильтр, FESMU отклоняет ответ и не выдаёт общую выборку пользователей.
При старте API автоматически применится `20261109120000_exam_assignments.sql`
из `migrations/test`. Удаление/переинициализация БД и ручной SQL не требуются.

Проверки с PostgreSQL запускаются только на отдельной тестовой БД:
`MDM_TEST_DB_DSN=... go test ./internal/storage -run TestUserDirectoryPostgres`.
Без этого параметра интеграционная проверка пропускается; модульные проверки
фильтров, query-параметров и отказа в запуске без назначения выполняются всегда.

## Одна попытка и результат преподавателю

В экзаменационном банке каждый вопрос должен иметь ровно один правильный
ответ. Редактор позволяет выбрать один вариант; API проверяет это при
сохранении и выдаче доступа. Ранее загруженные вопросы с несколькими верными
ответами нужно исправить перед выдачей. Импорт сохраняет исходные отметки,
не выбирая правильный ответ за преподавателя.

Результат экзамена студенту не передаётся, в том числе для старых сессий
с включённым `show_result`. После сдачи появляется сообщение, что результат
сообщит преподаватель. Оценки и ответы в преподавательском разделе сохраняются.

`exam_participations` связывает UUID студента MDM с предметом внутри факультета
и семестра. Название теста и новая сессия не сбрасывают попытку. Повторный старт
незавершённой попытки возвращает ту же попытку с исходным временем окончания;
параллельные запросы защищены уникальным индексом и транзакцией. Завершённый
предмет или предмет с истёкшим временем исчезает из открытого списка.
Удаление результата преподавателем удаляет связанную запись участия в одной транзакции и разрешает новую попытку, пока назначенная сессия открыта. Удаление самой сессии не сбрасывает ограничение.

При запуске API миграция `20261109180000_exam_once_policy.sql` автоматически
создаёт таблицу и переносит существующие попытки с UUID MDM. Исторические
попытки без UUID невозможно достоверно связать со студентом; они не участвуют
в этом переносе. Обычные тесты V1/V2 сохраняют прежнее поведение.

Проверка транзакции на отдельной PostgreSQL:
`EXAM_TEST_DB_DSN=... go test ./internal/storage -run TestExamOncePostgres`.

В деталях сессии показаны название выданного теста и все назначенные студенты,
включая тех, кто ещё не начинал: ФИО, группа, UUID MDM, дата выдачи и состояние
прохождения в этой сессии. ФИО и группа сохраняются при назначении; для старых
записей без ФИО выполняется пакетный запрос MDM по UUID. Недоступность MDM
не скрывает сохранённые назначения и результаты. Новые поля добавляются
автоматически миграцией `20261109190000_exam_recipient_identity.sql`.
