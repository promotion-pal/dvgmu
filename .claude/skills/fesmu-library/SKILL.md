# Сид библиотеки и методичек

Библиотека — модуль `library` в fesmu api (`apps/fesmu/api/internal/modules/library`, описание
в `doc.go`), база `library_db`. Сид — goose-миграция в `apps/fesmu/api/migrations/library/`.
api применяет её при старте, локально — при `make dev-up`. Методички вставляются
опубликованными (draft = published), их сразу видят студенты.

## Порядок работы

1. **Источник.** Прочитать файл пользователя целиком: конспект `.md`, текст пособия, список
   литературы. Выяснить, для какой кафедры и дисциплины материал. Если кафедра есть в
   `apps/fesmu/web/src/shared/config/departments.ts`, полное название берётся оттуда (поле authors).
2. **Исходники методичек** — `.md` в scratchpad, по одному файлу на методичку. Формат: свойства
   карточки, темы, вставки ```callout / checklist / case / quiz / glossary / video —
   `references/format.md`. Методическая часть и правила по фактам — `references/methodology.md`;
   прочитать до того, как писать текст.
   - Конспект пользователя: скопировать как есть, добавить свойства и методическую часть.
   - Выжимка из пособия: отдельная методичка по схеме разбора манипуляции.
3. **Сборка:**
   ```bash
   .claude/skills/fesmu-library/scripts/build.py --name <slug> \
     --comment "<что сеем, одной строкой>" [--items items.json] a.md b.md
   ```
   Одна миграция на один запрос пользователя. Скрипт сам проверяет формат и пределы api и
   печатает путь к миграции.
4. **Проверка:**
   ```bash
   .claude/skills/fesmu-library/scripts/check.sh <путь к миграции>
   ```
   Проверяет содержимое теми же функциями api, что и редактор (`decodeSections`,
   `checkSections`), и пересчитывает `atlas.sum`. Если запущен `make dev-up`, ещё и
   выполняет SQL в транзакции с откатом.
5. **Отчёт пользователю:** какие методички (темы и блоки) и издания добавлены, что добавлено
   сверх источника (задачи, тесты, выноски об устаревших нормах — их проверяет кафедра), как
   посмотреть (`make dev-up`, раздел «Методички»). Без просьбы не коммитить.

## Правила

- **Применённую миграцию не правят.** Если сид уже на сервере или в чьей-то базе, изменения
  делают новой миграцией (UPDATE по discipline и title) или в редакторе на портале. Пока
  миграция не применена нигде, её можно пересобрать с тем же `--out`.
- Сид не перезаписывает: методичка с той же дисциплиной и названием (издание с тем же title и
  url) остаётся как есть. Поэтому, чтобы заменить содержимое, нужен UPDATE, а не повторный сид.
- Рисунки, вложения и файлы изданий загружаются только через api (раздел «Библиотека» и
  редактор методички): сервис файлов регистрирует их в `library_files`.
- Исходники `.md` и `items.json` в репозиторий не кладут, в репозитории только миграция.
  Пользователю называют путь к исходникам в scratchpad, чтобы он мог попросить правки.
- Схему (`library.entity.proto`) и таблицы навык не меняет. Новый вид блока — это работа по
  навыку `fesmu-architecture` (proto → `make proto` → shared/blocks), после неё нужно
  дополнить `build.py` и `references/format.md`.
