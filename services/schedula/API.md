# Контракт Schedula

Клиент портала вызывает `/contract.schedula.service.SchedulaService/<Method>` через `VITE_API_URL`. Точные поля и номера определены в [сервисе](api/contract/schedula/service/schedula.service.proto), [сообщениях](api/contract/schedula/entity/schedule.entity.proto) и [перечислениях](api/contract/schedula/enum/schedule.enum.proto). Ниже имена полей даны в JSON-представлении Connect.

## Роли в действующем коде

Эта таблица описывает возможности работающих обработчиков и стартовые группы прав из миграции MDM. Назначение конкретному человеку определяется его эффективными правами. Для первой версии действует более узкая [ролевая матрица MVP](MVP.md#роли-и-права-первой-версии).

| Роль или набор прав сегодня | Что доступно сейчас | Изменение для MVP |
| --- | --- | --- |
| Студент без дополнительных прав | Личный календарь по активным группам, общая выдача в пределах студенческой проекции, базовый каталог. | Закрепить личную область на сервере. Закрыть общий каталог, выбор других групп и переходы в общую выдачу для новых данных. |
| Преподаватель без дополнительных прав | Личный и общий календарь, базовый каталог, заявка на изменение своего события, история своих заявок. В портале роль также допускается к подаче сведений. | Оставить просмотр своих опубликованных назначений. Убрать действия, доступ к заявкам и истории в новом контуре. |
| Группа MDM «Расписание: отдел расписания» | `schedule_drafts.post`, `schedule_publication.post`, `schedule_catalog.post`, `schedule_reports.fetch`, `schedule_changes.post`, а также портальные `schedule.post` и `schedule_intake.fetch`. Редактирование черновиков даёт и подбор слотов. | Использовать права черновиков для нагрузки и размещения, каталога для настройки, публикации для выпуска и прямой корректировки. Остаток в реестре доступен составителю при работе с нагрузкой. Права на входящие, согласования и расширенные отчёты для MVP не требуются. |
| Группа MDM «Расписание: отдел тестирования» | `schedule_testing.fetch` даёт общий календарь и подбор аттестационных слотов. | Вне состава ролей MVP. Проверить, что это право само по себе не открывает новый семестр. |
| Прочий сотрудник | Доступ определяется явными эффективными правами. Чтение `schedule` открывает календарь и базовый каталог. Сама роль сотрудника полномочий составителя не даёт. | Отсутствие назначения в отдел и личной учебной роли закрывает доступ к данным MVP. |
| Администратор платформы | Авторизация Schedula разрешает все секции активному администратору. | На приёмке использовать обычную учётную запись отдела. Для работы составителя нужны явно назначенные рабочие права, без автоматического допуска по технической роли. |
| Гость | `PublicScheduleFetch` и публичные представления, включая групповую ICS. | Новый семестр закрыт для анонимного чтения. Для прежних публикаций действует политика совместимости. |

## Кто может вызвать метод

Закрытые RPC требуют активной учётной записи. Допуск к чтению есть у студента, преподавателя, администратора или пользователя с подходящим эффективным правом. Для чтения секции подходит её `.fetch` или `.post`, для записи — `.post`. Администратор проходит все проверки секций. Сервис загружает права из MDM при каждом закрытом вызове. Реализация — [Authenticate](api/internal/grpc/auth.go) и [обработчики](api/internal/grpc/schedula.go).

| RPC | Доступ сегодня | Что получает клиент |
| --- | --- | --- |
| `PublicScheduleFetch` | Без сессии через шлюз. Межсервисный токен обязателен. | Публичные события, границы периода, учебная неделя, варианты дисциплин, корпусов и помещений за период. |
| `ScheduleFetch` | Допуск к чтению, в том числе по секции `schedule`. | События, периоды, отдельный список переносов, фактические даты и флаги возможностей. `personal` запрашивает назначения пользователя. |
| `CatalogFetch` | Допуск к чтению | Семестры, дисциплины, корпуса, помещения и действующие преподаватели. С правом записи `schedule_catalog` также периоды, праздники, нормы перехода и брони. |
| `CatalogSave` | `schedule_catalog.post` | В одной транзакции добавляет или обновляет переданные строки по их ключам. Пропущенные строки сохраняются. Ответ пустой. |
| `EventSave` | `schedule_drafts.post` | Без ID создаёт один черновик или серию. С ID и текущей ревизией заменяет данные одного черновика. Возвращает сохранённые события. |
| `EventCheckFetch` | `schedule_drafts.post` или `schedule_publication.post` | Проверяет сохранённую запись по ID с учётом черновиков. Возвращает список `issues`. |
| `EventPublish` | `schedule_publication.post` | Принимает ID и ревизию. При `series=true` для члена серии проверяет и публикует все оставшиеся черновики этой серии атомарно. Возвращает события и замечания. |
| `CompletenessFetch` | Чтение `schedule_reports` | Выдаёт пропуски по семестру. Каждое замечание указывает событие или учебную аудиторию (курс, группу, подгруппу). |
| `SlotsFetch` | `schedule_drafts.post` или чтение `schedule_testing` | Подбирает до 12 вариантов в пределах семестра за 1–31 день. Только редактор учитывает черновики и может исключить исходный экземпляр через `excludeEventId`. Без права редактирования допустимы экзамен, консультация, пересдача и ГИА. |
| `ChangeCreate` | `schedule_changes.post` либо преподаватель самого события | Принимает ID, ревизию, тип, причину и новые значения для этого типа. Создаёт ожидающую решения заявку либо возвращает замечания. |
| `ChangeDecide` | `schedule_changes.post` | Принимает ID заявки и решение. При отказе обязательно пояснение. При одобрении применяет изменение и записывает решение в одной транзакции. |
| `ChangeHistoryFetch` | `schedule_changes.post` либо преподаватель | История одного события в порядке подачи. С правом согласования выдаются все заявки, преподавателю без него — только поданные им. |

Черновики попадают в общую выборку при `includeDrafts=true`, `personal=false` и наличии права редактирования, публикации или отчётов. Доступность кнопок задают `canEdit`, `canPublish`, `canSearchSlots`, `canRequestChange`, `canReviewChanges`, `canViewReports`, `canEditCatalog`. Право работы с кафедрой, конкретной группой или дисциплиной потребуется проверять на сервере по подтверждённой области ответственности. Сейчас секции дают доступ к операции в целом, а для преподавателя при подаче заявки дополнительно сверяется ID назначенного преподавателя.

## Выборка и время

- Даты имеют формат `YYYY-MM-DD`, обе границы включены. Пустой период означает текущую неделю с понедельника по воскресенье по времени университета. Только `dateFrom` означает один день. Для произвольной выборки предел — 370 дней. `academicWeek` считается от понедельника первой недели семестра по первому дню пересечения запроса с семестром. Вне семестров значение равно нулю.
- Разные условия фильтра пересекаются. Внутри `types` подходит любой из перечисленных типов. Группа, курс и подгруппа должны совпасть в одном назначении. Группа или курс переключают сервер с личной на общую выборку. Фильтр выбирает среди разрешённых строк.
- Для личной выдачи студента MDM возвращает все его активные группы. В текущем адаптере отсутствует состав подгрупп. Студент с обычным доступом видит общегрупповые назначения. Указание подгруппы в запросе не подтверждает членство. Преподаватель видит назначения на свой ID.
- `PublicEvent` содержит ID, вид и статус события, дисциплину, коды групп, дату, начало, длительность, помещение, корпус, адрес и тип изменения. В публичном ответе отсутствуют ID преподавателей, подгруппы, составы, причины и история. Публичный RPC отклоняет фильтрацию по преподавателю и подгруппе.
- Начало — минуты от полуночи, длительность — фактические минуты. У черновика может отсутствовать `startMinute`, значение 0 означает полночь. Занятие помещается в одни сутки. При старте в 09:00 длительности 90, 120 и 180 минут дают окончания 10:30, 11:00 и 12:00. Правило пересчёта в академические часы требует согласования.

## Запись и проверки

1. **Черновик.** Минимум для `EventSave` — существующие семестр и дисциплина, допустимый тип, от 1 до 50 назначений с группой и курсом. Для серии указать начальную дату в `details`, конечную дату, повторение и недельные слоты в `series`. Понедельник имеет номер 1, воскресенье — 7. Еженедельное, чётное или нечётное повторение разворачивается в датированные экземпляры с собственными ID и общим `seriesId`. В одной серии допускается до 14 недельных слотов и до 370 экземпляров. При правке экземпляра передаются полные `details`.
2. **Проверка размещения.** Интервал занят от начала включительно до окончания исключительно. Проверяются пересечения групп и подгрупп, преподавателя, помещения и броней, часы работы, вместимость, оборудование и учебный период. Группа целиком пересекается с любой своей подгруппой. Для смежных занятий общих участников учитывается направленная норма перехода между площадками. Явный ноль — известная норма. При отсутствии нормы публикация и согласование возвращают предупреждение `TRAVEL_NORM_MISSING`. Автоматический подбор такой слот пропускает. Подбор возвращает примеры причин по типам, когда подходящих слотов нет.
3. **Клинический день.** Нужны подгруппа у каждого назначения, кафедра, преподаватель или наставник, клиническая база с адресом и точка сбора. Проверка преподавателя использует действующую роль преподавателя MDM. Отдельные дни могут проходить в разных помещениях. Для всех видов событий, кроме `COMPUTER_CLASS_TEST`, требуется преподаватель. Численность для целых групп берётся из MDM, если известна для всех назначений. Для подгрупп используется указанная численность.
4. **Публикация и праздник.** `EventPublish` повторяет проверки под транзакционной блокировкой. Блокирующее замечание в одном экземпляре оставляет весь выбранный набор черновиками. На праздник отдельная проверка укажет необходимость переноса. При публикации разрешён перевод такой даты в список переносов. В БД остаётся опубликованная запись, статус `TRANSFER` вычисляется в выдаче. `transfers` относится к семестрам, пересекающим запрос, и может содержать даты за пределами выбранной недели. Отмена остаётся видимой с отметкой `CANCELLED`.
5. **Изменение публикации.** Перенос меняет дату и начало, замена преподавателя — его ID, замена места — помещение и точку сбора, отмена — статус. У события может быть одна ожидающая заявка. Проверка при подаче и повторная при одобрении учитывают опубликованную занятость. При отказе событие сохраняет прежние значения. История хранит снимки до и после, причину, автора, время подачи, решение, согласующего и время решения.
6. **Полнота.** Отчёт ищет пропуски времени, места, преподавателя и клинических данных. Сопоставляет пригодные назначения со списком курсов и групп MDM и подгруппами из периодов семестра. Сверка дисциплин и часов с планом ещё нужна. В текущем коде отчёт и проверка публикации выполняются отдельно.

Записи проходят через [Storage.Write](api/internal/storage/storage.go) с общей транзакционной advisory-блокировкой PostgreSQL. Она защищает проверку и запись при конкуренции. Ревизия защищает от перезаписи из устаревшей формы. Создание нового события без ID при повторном вызове создаёт новый экземпляр.

## Как обработать ответ

В `EventPublish`, `ChangeCreate` и `ChangeDecide` успешный HTTP-ответ может содержать только `issues`. Подтверждать запись по непустому `events` или возвращённому `change`. Замечания могут сопровождать и успешную запись. У `Issue` есть тип, сообщение, ссылка на проверяемую запись и, где применимо, на конфликтующее событие или бронь. Для пары записей показать дату и интервал каждой. Текст сообщения предназначен для пользователя.

| Код Connect | Действие клиента |
| --- | --- |
| `InvalidArgument` | Сохранить введённые данные, показать причину и дать исправить ввод. |
| `Unauthenticated` / `PermissionDenied` | Проверить сессию или показать ограничение доступа. |
| `NotFound` | Обновить список и показать недоступность записи. |
| `FailedPrecondition` | При устаревшей ревизии или уже принятом решении перечитать объект. При нарушении ограничения справочника показать сообщение сервера. |
| `AlreadyExists` | Открыть историю ожидающей заявки в пределах прав пользователя. |
| `Unavailable` | Сообщить о недоступности справочника, предложить повтор чтения. При неопределённом исходе записи сначала перечитать состояние. |
